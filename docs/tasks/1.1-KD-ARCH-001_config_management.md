**任务ID:** `KD-ARCH-001`

---

**一、 背景信息:**

*   根据项目路线图 `Phase 1`，为提升项目的可配置性、可维护性和可测试性，需要将分散的配置项（如数据库路径、日志级别、引擎参数等）统一管理。引入 Pydantic 可以实现类型安全、结构化的配置管理，并将配置与代码逻辑分离。

----

**二、任务目标 (Objective):**

*   创建并实现基于 Pydantic 的分层配置管理系统，能够从环境变量或 `.env` 文件加载配置，并提供合理的默认值和验证机制。

**四、子任务列表:**

1.  **创建 `config.py` 文件:** 在 `knowledge_distiller_kd/core/` 目录下新建 `config.py`。
2.  **定义 Pydantic 模型:** 在 `config.py` 中定义以下 Pydantic 模型：
    *   `StorageConfig`: 包含 `database_url: str` (例如: `"sqlite+aiosqlite:///./instance/kd_default.sqlite"`) 等存储相关配置。
    *   `LoggingConfig`: 包含 `log_file_path: str = "logs/kd_tool.log"`, `log_level: str = "INFO"`, `log_rotation: str = "10 MB"`, `log_retention: str = "7 days"`, `log_serialize_json: bool = True` 等日志相关配置。添加 validator 确保 `log_level` 是有效的级别 (DEBUG, INFO, WARNING, ERROR, CRITICAL)。
    *   `EngineConfig`: 包含 `similarity_threshold: float = 0.85`, `czkawka_path: Optional[str] = None` (后续可通过 `utils.get_bundled_czkawka_path` 设置默认值) 等引擎核心参数。
    *   `AppConfig`: 聚合以上模型，如 `storage: StorageConfig = StorageConfig()`, `logging: LoggingConfig = LoggingConfig()`, `engine: EngineConfig = EngineConfig()`。
3.  **实现配置加载逻辑:**
    *   推荐使用 `pydantic-settings` 库（如果尚未安装，需添加到依赖）。
    *   让 `AppConfig` 继承 `BaseSettings`，并配置其优先从 `.env` 文件或环境变量加载，然后使用模型中定义的默认值。
    *   '''python
        # 示例 (config.py)
        from pydantic_settings import BaseSettings, SettingsConfigDict
        from typing import Optional

        class StorageConfig(BaseSettings):
            # 如果 .env 中有 DATABASE_URL，则使用它，否则使用默认值
            database_url: str = "sqlite+aiosqlite:///./instance/kd_default.sqlite"
            # model_config = SettingsConfigDict(env_prefix='STORAGE_') # 可选：为环境变量加前缀

        class LoggingConfig(BaseSettings):
            log_file_path: str = "logs/kd_tool.log"
            log_level: str = "INFO"
            log_rotation: str = "10 MB"
            log_retention: str = "7 days"
            log_serialize_json: bool = True
            # ... validator for log_level ...

        class EngineConfig(BaseSettings):
            similarity_threshold: float = 0.85
            czkawka_path: Optional[str] = None

        class AppConfig(BaseSettings):
            storage: StorageConfig = StorageConfig()
            logging: LoggingConfig = LoggingConfig()
            engine: EngineConfig = EngineConfig()

            # 配置 pydantic-settings 从 .env 文件加载
            model_config = SettingsConfigDict(env_file='.env', env_nested_delimiter='__', extra='ignore')

        # 单例模式或函数来获取配置实例
        _config_instance: Optional[AppConfig] = None
        def get_config() -> AppConfig:
            global _config_instance
            if _config_instance is None:
                _config_instance = AppConfig()
            return _config_instance

        '''
4.  **创建 `.env.example` 和 `.env` 文件:**
    *   `.env.example`: 包含所有可配置项的注释和示例值。
    *   `.env`: (本地使用) 可以覆盖 `.env.example` 中的值。
5.  **更新 `.gitignore`:** 添加 `.env` 文件。
6.  **(可选) 迁移常量:** 将 `core/constants.py` 中适合移入配置的常量（如默认阈值、路径等）迁移到 `config.py` 的模型默认值中，并移除旧常量。

**五、验收标准:**

1.  `knowledge_distiller_kd/core/config.py` 文件已创建，并包含定义的 `AppConfig`, `StorageConfig`, `LoggingConfig`, `EngineConfig` 模型。
2.  可以通过调用 `get_config()` (或类似方法) 成功加载 `AppConfig` 实例。
3.  加载配置时，优先使用 `.env` 文件或环境变量中的值覆盖 Pydantic 模型中的默认值。
4.  如果 `.env` 或环境变量未设置，则使用模型中定义的默认值。
5.  配置项的类型符合模型定义，不符合的类型或验证规则（如无效的 `log_level`）会引发 Pydantic 验证错误。
6.  `.env.example` 文件存在，并包含所有配置项的说明。
7.  `.gitignore` 文件已更新，包含 `.env`。
8.  (如果执行了迁移) `core/constants.py` 中相关的常量已被移除或更新。
9.  相关的单元测试已添加并通过（例如，测试不同覆盖场景下的配置加载、默认值、验证器）。
