**任务ID:** `KD-LOGGING-002`

---

**一、 背景信息:**

*   项目中可能存在使用 Python 标准 `logging` 模块或缺乏一致日志记录的情况。在 Task `KD-LOGGING-001` 完成 Loguru 的配置并通过工厂提供 logger 实例后，需要将整个项目的所有日志记录活动统一到使用这个配置好的 Loguru logger 上。

----

**二、任务目标 (Objective):**

*   全面审查并修改项目代码库 (`knowledge_distiller_kd` 目录)，将所有 Python 标准 `logging` 模块的导入和使用替换为通过工厂获取或直接导入的 `loguru.logger`。
*   确保所有日志记录点都使用新的 Loguru logger，并利用其特性（如 `bind()`）增强日志上下文。

---

**三、文件位置:**

*   所有 `.py` 文件在 `knowledge_distiller_kd/` 目录下 (潜在修改)
*   `knowledge_distiller_kd/core/engine.py` (使用注入的 `self.logger`)
*   其他核心模块或工具脚本 (可能直接 `from loguru import logger`)

---

**四、子任务列表:**

1.  **全局搜索旧日志代码:** 在整个 `knowledge_distiller_kd` 目录中搜索以下模式：
    *   `import logging`
    *   `logging.getLogger(...)`
    *   `logger.debug(...)`, `logger.info(...)`, `logger.warning(...)`, `logger.error(...)`, `logger.exception(...)` (当 `logger` 是标准库实例时)
2.  **替换日志调用:**
    *   对于通过依赖注入（如 `Engine` 中的 `self.logger`）获取 logger 的模块，直接使用该实例 (例如 `self.logger.info(...)`)。
    *   对于不需要注入、可以直接使用全局 logger 的模块或脚本（通常是工具类或辅助脚本），在文件顶部添加 `from loguru import logger`，然后直接使用 `logger.info(...)` 等。
    *   确保将标准库的日志级别调用正确映射到 Loguru 的对应方法。
3.  **利用 `bind()` 添加上下文:** 在适当的地方，使用 `logger.bind(key=value).info("Message with context")` 来自动添加结构化的上下文信息到日志条目中。例如，在处理特定文件时绑定 `file_path`。
4.  **处理 `exception()`:** 确保在 `except` 块中使用 `logger.exception("Error occurred")` 来自动记录异常信息和堆栈跟踪。
5.  **代码审查:** 仔细检查所有修改，确保没有遗漏，并且日志记录行为符合预期。

---

**五、验收标准:**

1.  项目中不再存在对 Python 标准 `logging` 模块的导入或使用（除了 Loguru 内部可能有的）。
2.  所有日志记录点均已迁移到使用 Loguru logger。
3.  通过依赖注入的 logger (如在 `Engine` 中) 被正确使用。
4.  在适当情况下使用了 `logger.bind()` 来增强日志上下文。
5.  异常被正确地通过 `logger.exception()` 记录。
6.  应用程序运行时，所有日志输出均由 Loguru 处理，并遵循 Task `KD-LOGGING-001` 中定义的配置。
