**任务ID:** `KD-ARCH-002`

---

**一、 背景信息:**

*   为实现依赖注入和集中管理，需要一个中心化的位置来创建和提供核心依赖项（如配置对象、存储实例、日志器），而不是在应用各处分散创建。

----

**二、任务目标 (Objective):**

*   创建并实现 `knowledge_distiller_kd/core/factories.py` 模块，提供用于创建和获取已配置的应用程序依赖（配置、存储、日志器）的工厂函数或类。

---

**三、文件位置:**

*   `knowledge_distiller_kd/core/factories.py` (新建)
*   `knowledge_distiller_kd/core/config.py` (读取 `AppConfig` 及 `get_config`)
*   `knowledge_distiller_kd/storage/storage_interface.py` (类型提示)
*   `knowledge_distiller_kd/storage/orm_storage.py` (实例化)
*   `loguru` (用于类型提示，日志器创建将在 Task 2.1 实现)
*   `knowledge_distiller_kd/core/engine.py` (Engine创建将在 Task 1.3 实现)

---

**四、子任务列表:**

1.  **创建 `factories.py` 文件:** 在 `knowledge_distiller_kd/core/` 目录下新建 `factories.py`。
2.  **实现配置获取函数:** 添加 `create_app_config() -> AppConfig` 函数，内部调用 `config.get_config()`。
3.  **实现存储实例创建函数:** 添加 `create_storage(config: AppConfig) -> StorageInterface` 函数。该函数接收 `AppConfig` 实例，读取 `config.storage.database_url`，创建并返回一个正确配置的 `ORMStorage` 实例。
4.  **添加日志器创建函数 (占位):** 添加 `create_logger(config: AppConfig)` 函数签名（具体实现将在 Task `KD-LOGGING-001` 中完成）。目前可以返回 `None` 或一个未配置的 `loguru.logger` 占位。
5.  **添加引擎创建函数 (占位):** 添加 `create_engine(storage: StorageInterface, config: AppConfig, logger)` 函数签名（具体实现将在 Task `KD-REFACTOR-001` 中完成）。

---

**五、验收标准:**

1.  `knowledge_distiller_kd/core/factories.py` 文件已创建。
2.  `create_app_config()` 函数可以成功返回 `AppConfig` 实例。
3.  `create_storage()` 函数可以接收 `AppConfig` 并返回一个配置正确的 `ORMStorage` 实例。
4.  `create_logger()` 和 `create_engine()` 函数签名存在。
5.  相关的单元测试已添加并通过（例如，测试 `create_storage` 使用了正确的配置）。

---

*   此任务为后续的任务 `KD-REFACTOR-001` (引擎注入) 和 `KD-LOGGING-001` (日志器实现) 提供基础。
*   考虑工厂是使用函数还是类实现（当前倾向于简单函数）。
