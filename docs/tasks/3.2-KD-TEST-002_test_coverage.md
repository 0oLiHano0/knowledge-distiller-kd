**任务ID:** `KD-TEST-002`

---

**一、 背景信息:**

*   Phase 1 和 Phase 2 引入了新的模块（Config, Factory）并对核心引擎（Engine）进行了重构以实现依赖注入和接口调用。为确保这些改动的正确性和稳定性，需要编写相应的单元测试和集成测试。

----

**二、任务目标 (Objective):**

*   为 `core/config.py`, `core/factories.py` 编写单元测试。
*   更新 `core/engine.py` 的单元测试以适应其新的依赖注入方式。
*   编写或增强集成测试，覆盖从应用启动到核心流程执行（包括配置加载、依赖创建、存储交互、日志记录）的端到端场景。

---

**三、文件位置:**

*   `tests/core/test_config.py` (新建)
*   `tests/core/test_factories.py` (新建)
*   `tests/core/test_engine.py` (修改)
*   `tests/test_integration.py` (新建或修改)
*   `conftest.py` (可能需要添加 fixtures, 如 Mock 对象或测试数据库设置)

---

**四、子任务列表:**

1.  **编写 `test_config.py`:**
    *   测试 `AppConfig` 能否正确加载默认值。
    *   使用 `monkeypatch` 或 Mock 修改环境变量/模拟 `.env` 文件，测试配置是否能被正确覆盖。
    *   测试 Pydantic 模型的验证逻辑（例如，提供无效的 `log_level`，预期引发 `ValidationError`）。
2.  **编写 `test_factories.py`:**
    *   测试 `create_app_config` 能否返回 `AppConfig` 实例。
    *   测试 `create_storage`：Mock `ORMStorage` 的 `__init__`，断言它被调用时传入了正确的 `database_url` (从 Mock 的 `AppConfig` 获取)。
    *   测试 `create_logger`：Mock `loguru.logger.add` 和 `remove`，断言它们被调用了正确的次数和参数（基于 Mock 的 `AppConfig`）。
    *   测试 `create_engine` (实现后)：Mock `Engine` 的 `__init__`，断言它接收到了正确的 `storage`, `config`, `logger` 实例。
3.  **更新 `test_engine.py`:**
    *   修改测试类的 `setUp` 或 fixtures，不再让 Engine 自己创建依赖。
    *   创建 Mock `StorageInterface`, Mock `AppConfig`, Mock `logger`。
    *   在测试 Engine 方法时，将这些 Mock 对象传递给 `Engine` 的构造函数。
    *   根据 Engine 方法的逻辑，设置 Mock 对象的返回值（例如 `mock_storage.get_blocks_by_file.return_value = [...]`）。
    *   断言 Engine 是否正确调用了 Mock 对象的方法 (`mock_storage.save_blocks.assert_called_once_with(...)`)。
4.  **编写/增强集成测试:**
    *   创建一个覆盖主要流程的集成测试函数/类。
    *   在测试开始时，可能需要设置一个临时的测试数据库和日志文件路径。
    *   模拟命令行调用或直接调用应用入口函数。
    *   执行应用的某个核心功能（例如，处理一个简单的文件）。
    *   断言：检查测试数据库中的数据是否符合预期；检查测试日志文件的内容和格式是否符合预期。
    *   在测试结束时清理测试数据库和日志文件。

---

**五、验收标准:**

1.  `test_config.py` 和 `test_factories.py` 存在，并通过测试。
2.  `test_engine.py` 已更新以使用 Mock 依赖，并通过测试。
3.  存在至少一个集成测试覆盖核心流程，并通过测试。
4.  测试覆盖率（如果测量）有所提高，覆盖了新代码和修改后的代码。
