**任务ID:** `KD-INTEGRATE-001`

---

**一、 背景信息:**

*   `KnowledgeDistillerEngine` 负责执行核心业务流程，其中涉及大量的数据持久化和检索操作（如保存文件记录、内容块、分析结果、用户决策等）。在 Task `KD-REFACTOR-001` 完成后，Engine 通过 `self.storage` 持有对 `StorageInterface` 实现的引用。现在需要将 Engine 内部所有的数据操作逻辑都通过这个接口进行。

----

**二、任务目标 (Objective):**

*   全面审查 `KnowledgeDistillerEngine` 的代码，将所有直接的文件系统读写或数据库交互（用于持久化目的）替换为调用注入的 `self.storage` 对象的相应方法。
*   确保在 Engine 和 Storage 之间传递的数据符合 `core.models.py` 中定义的 DTO 或 SQLAlchemy 模型规范。

---

**三、文件位置:**

*   `knowledge_distiller_kd/core/engine.py` (主要修改)
*   `knowledge_distiller_kd/storage/storage_interface.py` (查阅接口方法定义)
*   `knowledge_distiller_kd/core/models.py` (查阅和确保 DTO/模型一致性)
*   `knowledge_distiller_kd/processing/document_processor.py` (可能需要处理 ContentBlock 模型不一致问题)

---

**四、子任务列表:**

1.  **识别持久化代码:** 在 `engine.py` 中搜索所有执行数据保存、加载、查询、更新或删除的代码段，特别是涉及文件 IO (如 `json.dump`, `open()`) 或数据库连接/游标的部分。
2.  **映射到接口方法:** 对于每个识别出的代码段，找到 `StorageInterface` 中对应的抽象方法（例如，保存内容块对应 `save_blocks`，加载决策对应 `get_user_decisions` 等）。
3.  **替换实现:** 将旧的持久化代码替换为对 `self.storage.method_name(...)` 的调用。
4.  **数据模型对齐:**
    *   仔细检查传递给 `self.storage` 方法的参数类型和从方法返回的数据类型。
    *   确保使用的是 `knowledge_distiller_kd/core/models.py` 中定义的 DTO（如 `BlockDTO`, `FileRecord`, `UserDecision`）或 ORM 模型，而不是其他地方（如 `processing` 层）定义的临时结构。
    *   特别注意解决架构文档中提到的 `processing.document_processor.ContentBlock` 与 `core.models.BlockDTO`（或对应的 `core.models.ContentBlock`）的不一致问题。可能需要在 Engine 或 Processing 层添加转换逻辑。
5.  **处理返回值:** 根据 `StorageInterface` 方法的返回值（例如，返回获取的数据列表，或表示操作成功的布尔值），调整 Engine 中的后续逻辑。

---

**五、验收标准:**

1.  `engine.py` 中不再包含任何用于持久化目的的直接文件 IO 或数据库访问代码。
2.  所有的数据持久化和检索操作均通过调用 `self.storage` 对象的接口方法完成。
3.  在 Engine 和 Storage 接口之间传递的数据类型严格符合 `core/models.py` 的定义。
4.  `processing` 层与 `core` 层之间关于 `ContentBlock` 的模型不一致问题已得到解决（通过统一或转换）。
5.  依赖于持久化操作的 Engine 功能在修改后仍然按预期工作。
6.  相关的单元测试和集成测试已更新并通过。
